# 草莓猫桌宠配置说明

骨骼版将当前用户的设置保存到 `%LocalAppData%\DesktopPet.Skeletal\settings.json`，与原版独立。设置窗口提供日常调整入口；动画姿态顺序和时间槽存放在角色素材的 `manifest.json` 中，两者独立管理。

默认使用“日常陪伴”，可在设置、猫咪右键菜单或托盘选择“工作模式”。模式和时长会保存，缺少新字段时保持日常陪伴。

设置页按陪伴方式、桌面显示和相伴记录分组，只展开当前模式相关的选项。工作与休息优先选择 25/5、50/10、45/15 分钟组合，需要其他时长时再选择自定义；日常自动入睡提供 1、5、15 分钟和自定义。关闭自动入睡会收起入睡时长。已有自定义时长会原样保留，选择“自定义”本身不会改写数值。

待机动作最短／最长间隔、自动起身停留、点击冷却、悬停唤醒判定不再作为设置页输入项，日常使用无需调整。对应配置字段仍受支持，修改其他设置不会覆盖这些既有值。

日常互动方式为“悬停唤醒、点击互动”：悬停会打断入睡或唤醒睡眠，完成后保持趴坐；清醒时悬停只更新互动时间。单击随机喵叫或 Wink，两者机会相同；双击固定喵叫。睡眠中点击先唤醒再互动，重复悬停不会取消点击。起身和萤火虫待机过程中点击，会等完整收尾后回应一次；点击回应期间不叠加、不排队，两种点击动作共用冷却。

工作模式默认工作 25 分钟、休息 5 分钟，循环执行。进入工作时喵叫并显示“开始工作啦~”；工作中点击只显示“工作呢，别打扰我”。到点后退出电脑场景，Wink 并显示“休息一下吧~”，随后入睡。休息中点击会唤醒、打哈欠并显示“和我一起休息”，再继续睡；悬停不会叫醒它。休息到点后唤醒并开始下一轮。

工作计时从 `work_loop` 开始，休息计时从本轮首次 `sleep_loop` 开始。休息中点击回应所用的时间仍计入本轮休息，不重置计时；若回应结束时已到点，就开始下一轮。模式和时长会跨重启保留，当前阶段与剩余时间不保存，重启工作模式从新一轮开始。

开启成长记录和陪伴短句后，每次实际被接受的日常单击或双击都显示一条当前关系阶段的短句，不再显示单字“喵”；原有动作及点击冷却保持不变。工作、休息提示也会按关系阶段替换，工作中的忙碌回应保留原文。关闭陪伴短句后，日常点击仅保留动作，工作和休息仍有基础提示。关闭成长记录或存档不可用时也不回退单字“喵”。

## 配置字段

JSON 字段采用下表中的名称。时间统一以毫秒保存；设置页面的自定义工作和休息输入使用分钟，日常自定义入睡使用秒，均支持小数。角色尺寸仍以 DIP 保存并随系统 DPI 缩放，界面用大小滑块和相对默认大小的百分比表达。日常待机池为眨眼、打哈欠、起身右瞥、萤火虫，权重为 2:1:1:1，每次独立抽样，允许重复。`blinkMinMs` / `blinkMaxMs` 保留旧字段名，控制动作结束后到下一次选择的等待时间。Wink 全程 1500ms，不受起身保持设置影响。

| 字段 | 类型 | 默认值 | 约束与作用 |
| --- | --- | --- | --- |
| `schemaVersion` | 整数 | `1` | 当前只支持版本 1。 |
| `mode` | 字符串 | `"daily"` | `"daily"` 为日常陪伴，`"work"` 为工作模式；不接受数字枚举。 |
| `workDurationMs` | 整数 | `1500000` | 每轮工作时长，1 至 28,800,000 毫秒（8 小时）；仅工作模式使用。 |
| `breakDurationMs` | 整数 | `300000` | 每轮休息时长，1 至 28,800,000 毫秒；仅工作模式使用。 |
| `autoSleep` | 布尔值 | `true` | 日常模式无交互自动入睡；不控制工作模式的定时休息。 |
| `blinkMinMs` | 整数 | `3000` | 待机动作间隔下限，1 至 86,400,000 毫秒。 |
| `blinkMaxMs` | 整数 | `8000` | 待机动作间隔上限，1 至 86,400,000 毫秒，且不小于下限。每次待机动作结束重新抽取间隔。 |
| `sleepAfterMs` | 整数 | `60000` | 无桌宠交互后的入睡期限，1 至 604,800,000 毫秒；其他软件中的键鼠输入不刷新此计时。 |
| `triggerMode` | 字符串 | `"hover"` | 兼容旧配置保留，接受 `"hover"` / `"click"`。两种旧值均采用悬停唤醒、单击随机喵叫或 Wink，设置页不再提供二选一。 |
| `hoverDwellMs` | 整数 | `120` | 实际移入身体后保持命中的时间，1 至 10,000 毫秒。静止停留不重复触发。 |
| `holdMs` | 整数 | `1000` | 自动起身后的保持时间，1 至 60,000 毫秒；静止悬停不延长它。 |
| `cooldownMs` | 整数 | `1000` | 一次反应完成后的冷却时间，0 至 60,000 毫秒；冷却内有效交互仍刷新入睡期限。 |
| `petHeightDip` | 数值 | `240` | 角色画布显示高度，120 至 480 DIP；宽度按素材画布比例计算。必须为有限数值。 |
| `topmost` | 布尔值 | `true` | 使宠物窗口保持置顶。 |
| `clickThrough` | 布尔值 | `false` | 开启后整只猫允许鼠标穿透，触碰和拖拽暂停；可从托盘关闭。默认仅完全透明空白区域交由系统穿透。 |
| `startWithWindows` | 布尔值 | `false` | 由用户在设置页显式开启或关闭当前用户的登录自启动。 |
| `companionshipEnabled` | 布尔值 | `true` | 记录相伴成长；关闭后暂停新成长与回忆，保留已有关系和记录。重新开启后需一次主动使用开始计时。 |
| `companionTextEnabled` | 布尔值 | `true` | 显示陪伴短句；关闭后日常点击不显示文字，保留原动作、成长记录及基础工作／休息提示。 |
| `position` | 对象或 `null` | `null` | 保存显示器和工作区内的相对位置；首次启动或显示器不存在时使用可见工作区。 |
| `position.monitorId` | 字符串 | 对象默认 `""` | 显示器设备标识，由应用保存，例如 `\\.\DISPLAY1`。 |
| `position.relativeX` | 数值 | 对象默认 `0.8` | 0 至 1，表示窗口左侧在工作区可移动水平范围中的比例。 |
| `position.relativeY` | 数值 | 对象默认 `0.8` | 0 至 1，表示窗口顶部在工作区可移动垂直范围中的比例。 |

`position` 为 `null` 时不使用对象内部的 `0.8` 默认值，应用会在主显示器可见工作区靠右下的位置首次放置角色。相对位置的可移动范围已经扣除了窗口自身宽高，便于重启或工作区变化后保持完整可见。

完整默认配置示例：

```json
{
  "schemaVersion": 1,
  "mode": "daily",
  "workDurationMs": 1500000,
  "breakDurationMs": 300000,
  "autoSleep": true,
  "blinkMinMs": 3000,
  "blinkMaxMs": 8000,
  "sleepAfterMs": 60000,
  "triggerMode": "hover",
  "hoverDwellMs": 120,
  "holdMs": 1000,
  "cooldownMs": 1000,
  "petHeightDip": 240,
  "topmost": true,
  "clickThrough": false,
  "startWithWindows": false,
  "companionshipEnabled": true,
  "companionTextEnabled": true,
  "position": null
}
```

## 应用与保存

设置页在当前操作相关参数通过校验后即时应用；另一模式中隐藏的时长输入不会阻碍当前设置保存，仍沿用已保存的合法值。连续调整合并为约 600 毫秒后写盘；拖拽结束保存最终位置，应用退出时再次提交未保存内容。非法参数会显示错误，不会替换正在使用的合法配置。

写盘先在同一目录创建 `settings.json.tmp`，刷新文件后原子替换正式文件。保存失败时保留旧文件，并在设置页或托盘提示失败；当前进程仍可能使用尚未落盘的新值，重启后以最后成功保存的文件为准。

旧配置缺少字段时，缺少项采用默认值，包括日常模式与 25/5 分钟。损坏 JSON、非法值或不支持的版本会使应用使用默认设置，并尝试将原文件复制为 `settings.json.invalid-时间戳.bak`。备份失败会记录日志。设置页的“恢复默认”恢复模式、时长、行为、尺寸和开关，同时保留当前窗口位置，并立即保存。

如需手工编辑，先从托盘退出桌宠，再修改 JSON 并重新启动。当前应用不监听外部文件修改；运行中修改文件可能被后续自动保存覆盖。`mode` 与 `triggerMode` 使用字符串，不能用数字枚举代替。

## 自启动与托盘开关

自启动通过当前用户注册表项 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中名为 `TablePet` 的值实现，不需要管理员权限。只有在设置页改变自启动选项时才更新此项；手工修改 JSON 不会自动安装或移除启动项。移动应用文件夹后，如仍需要自启动，应在新位置运行应用并重新关闭、开启该选项。

模式选择会持久化。暂停和“显示／隐藏”是当前运行会话的控制状态，不写入上述 JSON。日常模式的“暂停自动动作”让当前动作自然收尾，不再安排新的待机动作或入睡，点击互动仍可用；工作模式的“暂停工作／休息计时”则立即冻结动画、气泡与当前轮次计时，继续后接着运行。

拖拽、隐藏、系统锁屏或挂起也会冻结工作场景及工作／休息计时，恢复时不补算暂停期间的时间。整窗穿透与置顶属于持久化设置。工作素材不完整时，控制器回退到日常陪伴，猫咪右键和托盘中的工作入口不可用。

## 相伴记录

右键菜单、托盘和设置页均可打开“我们的日常”。概览卡集中展示当前关系、累计相伴日、四个阶段及下一阶段进度，当前阶段有文字标记；具体数值和条件收在“成长说明”中。回忆按获得顺序倒序排列，标题与正文优先、日期置于下方，保留专属插画，仅统计已留下的回忆数量。页头与关闭按钮固定，回忆可独立滚动；空记录、暂停记录和存档异常均有相应提示。点击小猫仍用于摸猫互动。

有效互动、主动选择或继续工作，以及打开日常面板，会开启 30 分钟的陪伴计时窗口。此期间，小猫可见且系统会话可用才累计；每天满 1 分钟记为一个相伴日，满 20 分钟达到每日熟悉度上限。离开不扣分，不要求连续使用。打开设置、自动启动或自动进入下一轮工作本身不会开启计时窗口。规则详见 [成长设计](COMPANIONSHIP-DESIGN.md)。

成长独立保存在 `%LocalAppData%\DesktopPet.Skeletal\companion-state.json`，不随设置页“恢复默认”清空。保存使用同目录临时文件和原子替换，上一份正常存档保存在 `.bak`。读取异常时会尝试备份恢复并在面板提示；无可用备份时暂停记录，原文件保留。较新版本的存档不会被旧应用覆盖或重置。已有旧设置的用户从本次更新后的主动使用开始记录，不推算历史日数。

开发验收可使用独立目录，例如：

```powershell
.\TablePet.Skeletal.exe --data-dir C:\Temp\TablePet-Preview --companion
.\TablePet.Skeletal.exe --data-dir C:\Temp\TablePet-Preview --quit
```

`--data-dir` 将设置、相伴存档和单实例通信隔离；`--companion` 首次启动时打开面板。该参数用于本地验收，不隔离公共错误日志或 Windows 登录自启动注册表项；预览时不要修改自启动选项。

## 日志

日志位于 `%LocalAppData%\DesktopPet.Skeletal\TablePet.log`，用于记录加载、保存及平台操作异常。单个日志超过约 256 KiB 后轮换为 `TablePet.log.previous`。日志不记录逐帧绘制或持续鼠标移动。
