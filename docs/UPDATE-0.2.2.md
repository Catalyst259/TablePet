# 0.2.2 睡眠呼吸优化记录

2026年10月27日。本版仅优化睡眠时的身体起伏，不调整已确认的眨眼和互动规则。最终素材已完成逐帧、深浅背景、循环衔接和无窗口播放性能检查。

## 问题与调整

旧睡眠片段已经持续循环，并非只播放一张静态图。但基准睡姿到吸气峰值，在512像素素材画布上轮廓顶部仅移动1像素；默认240 DIP显示时约为0.47 DIP，本机150%缩放下不足1个物理像素。身体起伏难以察觉，是本轮优先修正的问题。

使用内置image_gen，以现有闭眼睡姿为编辑基准生成吸气姿态。经候选比较，选择第二候选，并只采用原睡姿到新候选之间 **25%的RIFE相位**，把完整吸气幅度收敛到克制的小起伏。最终眼部和头饰同步上升6个素材像素，默认240DIP尺寸对应2.8125DIP；前爪落地，头饰跟随头部保持形状。

循环保留3.6秒一轮，使用240Hz素材时间轴，吸气峰值和循环交界处缓入缓出。素材由现成RIFE 4.6补帧，运行时继续使用已有WPF播放器，不增加在线模型依赖或自制渲染引擎。

初次逐帧验收发现RIFE第一张推理图有非零重建残差：即使循环首尾使用同一原图，从原图进入首张推理图仍会闪变。改用现成FFmpeg 8.1.1浮点预乘alpha合成，仅在最靠近原睡姿的1–15相位使用smoothstep过渡；第0相位保持原图，第16相位起保持RIFE输出。首帧过渡的可见像素平均差由5.2922降至0.0575，最大通道差由189降至3，放大检查未见双轮廓或边缘暗圈。该处理仅用于离线制作，用户运行桌宠无需FFmpeg。

## 衔接与范围

- 入睡最后一帧、睡眠循环首尾、唤醒第一帧共用原始基准睡姿，避免循环接缝和片段切换时跳变。
- 任意呼吸相位收到唤醒时，沿既有路径平滑返回基准睡姿，再接唤醒；无须等待整轮呼吸。
- 待机、眨眼、入睡、唤醒、起身、保持、蹲下这7个片段保持原内容。
- 悬停只唤醒并保持趴坐，点击才起身；拖拽和眨眼中的既有处理保持不变。
- 0.2.1安装包、便携包及源码ZIP保留，0.2.2使用独立版本目录。

关键帧与幅度配置保存在 `assets/strawberry-cat/keyframes-v4/sleep`，原始生成结果在 `assets/strawberry-cat/sources/sleep-v4`，提示词在 `reference/sleep-v4-prompts.json`，0.2.1素材清单基线为 `reference/motion-v3/manifest.json`。重建命令为 `node tools/touchup-sleep.cjs`，完整 `npm run assets:prepare` 也包含该步骤。单独重建眨眼会保留这版睡眠循环及较新的素材版本。
